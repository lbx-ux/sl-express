# 压测方案（总纲）

> 项目：神领物流 · 简历技术点实测验证系列
> 目标：为简历中的核心技术选型与设计方案提供可复现的压测数据支撑。
> 总原则：**数字的说服力不来自大小，来自对比**——每个实验都设计 baseline，孤立绝对值不写进简历。

## 实验设计的通用守则

1. **每个数字必须有 baseline**：以「提升 X 倍 / RT 从 A 降至 B」的形式呈现，孤立绝对值不写进简历。
2. **统一压测口径**：预热 1 轮丢弃（避免冷启动污染）、持续时间 ≥ 120s、以 TP99/TP999 为主要指标（平均值仅参考）。
3. **环境口径如实呈现**：测试环境为 2C 虚拟机 + Docker 容器，绝对值低于生产硬件属正常；面试时主动说明环境，与官方数据对照反而体现专业度。
4. **自洽校验（Little's Law）**：QPS × 平均 RT ≈ 并发数，各指标间不得互相矛盾。
5. **数据隔离**：压测数据以专用标识段（bid 9200001+ / biz_tag bench_stress / BENCH- 前缀）与真实数据隔离，测后可精确清理。
6. **参数合法性前置核对**：设计压测参数前核对服务端枚举、校验逻辑（实验四的 type=9 NPE 教训）。

- 压测工具：JMeter 5.6.3（jmx 文件按实验存放于 `experiment2/3/4/5` 目录）
- 数据生成：Python 脚本（标准库，固定随机种子保证可复现）
- 虚拟机：192.168.150.101（ssh 已配免密），MySQL/MongoDB/Neo4j/Leaf 均为 Docker 容器
